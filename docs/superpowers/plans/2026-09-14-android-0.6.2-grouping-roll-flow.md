# Android 0.6.2 Grouping and Roll Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Android 0.6.2 with restored development trees, full drag-and-drop ordering, non-blocking martial arts navigation, stable sheets, independent two-column layout, and explicit per-roll attribute selection.

**Architecture:** Keep `SheetGroup.itemIds` as the persisted outer-order source and derive development hierarchy from existing `DevelopmentSheetItem.parentId`. Add pure model helpers for block/tree movement and column balancing, then make Compose render and drag against those helpers. Split attribute selection from the existing roll sheet so every character-sheet skill tap starts from the stock attribute.

**Tech Stack:** Kotlin, Jetpack Compose Material3, existing JSON catalogs and pure Kotlin model tests.

**Spec:** `docs/superpowers/specs/2026-09-14-android-0.6.2-grouping-roll-flow-design.md`

## Global Constraints
- Preserve existing character saves from 0.6/0.6.1.
- Do not remove user-created groups.
- Parent drag moves the entire subtree; child drag moves only that child.
- Groups reorder only through drag-and-drop; remove up/down controls.
- Skill roll always begins with the stock attribute.
- No eager all-entry Martial Arts availability computation during normal browsing.
