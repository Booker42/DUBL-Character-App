# DUBL Desktop 0.2 Android Functional Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver DUBL Desktop 0.2 with functional parity to canonical Android 0.6.2 and a click-to-run Linux release.

**Architecture:** Move Android mutation semantics into shared sessions, keep catalogs/rules canonical, use platform adapters for persistence/resources, and compose desktop-native screens over the shared application layer. Desktop must never duplicate game formulas.

**Tech Stack:** Kotlin Multiplatform, Compose Multiplatform Desktop, Kotlin/JVM file adapters, Android Jetpack Compose, JSON catalog resources, Linux AppImage packaging.

**Spec:** `docs/superpowers/specs/2026-09-15-desktop-0.2-android-parity-design.md`

## Global Constraints

- Android 0.6.2 is the source of truth for behavior and data.
- Web/Wasm, server/accounts, and sync are out of scope.
- Old PySide/Electron desktop is not a source of rules or architecture.
- No horizontal scrolling.
- Shared commonMain must remain platform-independent.
- Schema 7 character data must remain compatible.
