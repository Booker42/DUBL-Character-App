# Android 0.6.2 grouping, roll flow, and performance design

## Goal
Restore rule-aware hierarchy for special skills and martial arts without giving up user-defined groups and drag-and-drop ordering, remove the martial-arts entry freeze, stabilize bottom-sheet gestures, and require an explicit attribute choice before every skill roll.

## Grouping model
- User groups remain the outer organization on the character sheet.
- System hierarchy remains metadata inside each user group. Parent/child links come from `DevelopmentSheetItem.parentId`/`depth` and are never destroyed by custom grouping.
- When parent and child are in the same user group, the child is rendered nested under that parent automatically.
- Siblings preserve explicit user order and can be reordered independently.
- Dragging a parent entry as a tree moves that parent and every current descendant in its subtree as one contiguous block to the target group/position.
- Dragging a child entry moves only that entry. If separated from its parent, it renders as a root in the target group. If later moved into the same group as its parent, the hierarchy reconnects automatically.
- Groups themselves are reordered by drag-and-drop. Up/down group buttons are removed.
- The serialized format remains backward-compatible with 0.6/0.6.1 `SheetGroup.itemIds`; tree behavior is derived from catalog metadata, so migration is normalization rather than a schema reset.

## Character-sheet layout
- Skills and development cards use two independent vertical columns rather than row chunking. Each item goes to the currently shorter column in stable input order.
- A tall two-line card in one column must not reserve matching height in the other column.
- Development tiles show hierarchy with compact indentation/branch markers, while preserving tap targets and two-column density.

## Skill roll flow
- Tapping a skill always opens an attribute-selection sheet first.
- Default selection is the stock/default skill attribute (`skill.attributes.first()`), regardless of any prior choice.
- Selecting another legal attribute immediately recalculates and displays the exact bonus/formula for that attribute.
- User confirms with `К броску`, then the existing roll sheet opens using the chosen attribute.
- Previous `preferredSkillAttributes` data is retained for backward compatibility but no longer controls this flow.

## Martial arts performance
- Entering Martial Arts must not compute `DevelopmentRules.availability()` for every catalog entry.
- Availability is evaluated lazily per visible row. Bulk availability evaluation is permitted only for the explicit `Доступно сейчас` filter because filtering requires it.
- Search/category grouping must remain cheap and must not run requirement evaluation unless required.

## Bottom sheets
- Remove custom nested-scroll consumption that fights Material3 sheet drag behavior.
- Use one consistent Material3 sheet state with partial expansion skipped for affected sheets.
- Scrollable content remains scrollable; downward overscroll at the top is left to the sheet so drag-to-dismiss is stable.

## Verification
- Unit tests cover block/tree movement, child extraction/relinking, group reordering, backward normalization, and independent-column layout assignment.
- Regression checks verify martial-art availability is not eagerly enumerated in normal view.
- Existing rule/content regression suite must remain green.
